# Simple Tasks — актуальные требования

Состояние: 0.57.0, проверено по репозиторию 10.11.2026. Исполнитель фичи — Claude Code или Codex.
Цель: персональный локальный трекер задач Android 10+ с импортом/экспортом TickTick, виджетом и напоминаниями.
Правила разработки — [AGENTS.md](AGENTS.md).

## 1. Основные ограничения

- Приложение работает с локальной Room/SQLite; схема БД — версия 5.
- Обновления должны сохранять пользовательские данные. Миграции обязательны при изменении схемы.
- Обычное удаление задачи отправляет её в корзину; восстановление и окончательное удаление — отдельные действия.
- Общая логика операций должна одинаково работать из приложения, виджета и уведомлений.
- Вибрацию не добавлять: решение PM. PM преимущественно пользуется виджетом и уведомлениями.
- Текущая схема: [AppDatabase](app/src/main/java/com/prostovasei/simpletasks/data/local/db/AppDatabase.kt)
  и [экспорт Room v5](app/schemas/com.prostovasei.simpletasks.data.local.db.AppDatabase/5.json).
  Таблицы из старой спецификации не являются актуальной схемой.

## 2. Задачи и списки

- Задача: название, описание, список, дата/время или весь день, интервал, повтор, напоминания, чек-лист.
- Приоритетов два: обычный (0) и высокий (5). При импорте средний TickTick (3) становится высоким, низкий (1) — обычным.
- Статусы: активна (0), выполнена (2), «Не буду делать» (-1). Корзина учитывается отдельно через мягкое удаление.
- «Входящие» — неразобранные задачи без даты и пользовательского списка.
- «Когда-нибудь» — задачи со списком без даты; «Без списка» — с датой без пользовательского списка.
- Папки и списки поддерживают эмодзи. На экране «Списки» три группы: системные, пользовательские, архивные.
  У строк показывается ненулевое количество задач; внизу — поиск, новая папка, новый список, настройки.
- Поддерживаются поиск, массовые действия, выполнение и отмена действия, восстановление из корзины.
- Импорт и экспорт TickTick сохраняют поддерживаемые данные; реальная выгрузка пользователя хранится вне репозитория.

## 3. Навигация и окно задачи

- Нижняя панель: «Предстоящее» или «Неделя», «+», «Списки».
- Удержание левого пункта выбирает «Предстоящее»/«Неделя»; выбор запоминается.
- «Входящие», поиск и настройки открываются через «Списки».
- Создание/редактирование используют общую шторку задачи; из виджета задача открывается поверх рабочего стола.
- Окно даты содержит календарь и сетку задач; пересекающиеся интервалы располагаются рядом.
- Кнопка «Отложить» в окне задачи, уведомлении и полоске использует общие варианты переноса.

## 4. Повторы и напоминания

- RRULE и будущие повторы уже реализованы; это не будущая фича v1.1.
- Изменение даты повторяющейся задачи различает текущий повтор и все повторы с этого момента.
- Выполнение/«Не буду делать» и удаление серии имеют разные последствия; сохранять правила итераций 49–51.
- «Отложить» переносит срок задачи; варианты зависят от наличия времени. Детали — итерации 53–54.
- Напоминания, полоска поверх других приложений и утренняя озвучка работают средствами Android.
- При изменении этих правил проверять приложение, виджет и уведомления вместе.

## 5. Виджет и внешний вид

- Виджет поддерживает ленту и «Неделю»; операции доступны без перехода в основной экран приложения.
- Нижняя строка 0.57.0: «+» слева, общий белый блок вкладок по центру, дата справа.
  Выбранная вкладка — чёрный значок; «+» и дата одинаковой ширины.
- Нажатие даты возвращает к сегодня; свободного места строки — открывает приложение.
- Текущий стиль: нейтральный фон, чёрный акцент, высокий приоритет фиолетовый, шрифт Manrope.
- Цвета, размеры и компоненты — из дизайн-системы; новые изменения UI сначала согласуются на макете.
- Утверждённые варианты и способы воспроизведения — [design/README.md](design/README.md).

## 6. Где искать подробности и что считать готовым

Подробные решения по итерациям сохранены в [ARCHITECTURE.md](docs/ARCHITECTURE.md):
49–51 — повторы; 52 — системные разделы; 53–54 — отложить; 55–57 — навигация, списки, виджет.
Этот документ — актуальная сводка, а не пересмотр ранее согласованных деталей.

Новые требования фиксируются в GitHub Issue с критериями готовности и затем обновляют эту спецификацию.
Готовность фичи: реализованы критерии, пройдены проверки, обновлены документы и HANDOFF, PR объединён,
результат сборки доступен PM. Результат ручной проверки на телефоне фиксируется отдельно.
Проверки — [docs/TESTING.md](docs/TESTING.md).

Историческая спецификация с первоначальными схемами и планами сохранена [отдельно](docs/history/SPEC-before-2026-11-10.md).
Упоминания синхронизации, web, AI-ввода и тегов в ней не являются поручением на реализацию.

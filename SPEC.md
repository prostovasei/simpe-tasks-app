# ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ (SPEC.md)

**Продукт:** Персональный таск-трекер (Android MVP)
**Роль заказчика:** Product Manager
**Исполнитель реализации:** Claude Code

> **Ключевая цель MVP:** Создание высокоскоростного локального таск-менеджера без визуального шума с поддержкой полной миграции из TickTick и интерактивным виджетом на домашнем экране Android.

---

## 1. Общие сведения и архитектурные принципы

- **Целевая платформа:** Android 10+ (API Level 29+).
- **Технологический стек:** Kotlin, Jetpack Compose, Material 3, Room (SQLite), Jetpack Glance (AppWidget), Navigation Compose, Coroutines & Flow.
- **Архитектурный паттерн:** Single-Activity, Clean Architecture + MVI (Model-View-Intent).
- **Local-First & Sync-Ready:**
  - Все первичные ключи генерируются на клиенте в формате `UUIDv4` (String).
  - Физическое удаление строк запрещено — мягкое удаление (`is_deleted = 1`).
  - Каждая сущность хранит временные метки создания и обновления в миллисекундах UTC (`created_at`, `updated_at`).

## 2. Схема базы данных (Room Database Schema)

### 2.1. Таблица: `project_groups` (Папки списков)

| Поле | Тип данных | Ограничения | Описание |
|---|---|---|---|
| `id` | `TEXT` (String) | PRIMARY KEY | UUIDv4 папки |
| `name` | `TEXT` (String) | NOT NULL | Название папки |
| `sort_order` | `INTEGER` (Int) | DEFAULT 0 | Порядок отображения в меню |
| `is_deleted` | `INTEGER` (Boolean) | DEFAULT 0 | Флаг мягкого удаления |
| `created_at` | `INTEGER` (Long) | NOT NULL | Время создания (UTC, ms) |
| `updated_at` | `INTEGER` (Long) | NOT NULL | Время обновления (UTC, ms) |

### 2.2. Таблица: `projects` (Списки задач)

| Поле | Тип данных | Ограничения | Описание |
|---|---|---|---|
| `id` | `TEXT` (String) | PRIMARY KEY | UUIDv4 списка |
| `group_id` | `TEXT` (String?) | NULLABLE, FK | Ссылка на `project_groups.id` |
| `name` | `TEXT` (String) | NOT NULL | Название списка (напр. «Работа») |
| `color` | `TEXT` (String?) | DEFAULT NULL | HEX-цвет списка (напр. `#3D8BFD`) |
| `sort_order` | `INTEGER` (Int) | DEFAULT 0 | Порядок в списке |
| `is_inbox` | `INTEGER` (Boolean) | DEFAULT 0 | 1 для системного списка «Входящие» |
| `is_deleted` | `INTEGER` (Boolean) | DEFAULT 0 | Флаг мягкого удаления |
| `created_at` | `INTEGER` (Long) | NOT NULL | Время создания (UTC, ms) |
| `updated_at` | `INTEGER` (Long) | NOT NULL | Время обновления (UTC, ms) |

### 2.3. Таблица: `tasks` (Задачи)

| Поле | Тип данных | Ограничения | Описание |
|---|---|---|---|
| `id` | `TEXT` (String) | PRIMARY KEY | UUIDv4 задачи |
| `project_id` | `TEXT` (String) | NOT NULL, FK | Ссылка на `projects.id` |

| `priority` | `INTEGER` (Int) | DEFAULT 0 | `0` = None, `1` = Low, `3` = Med, `5` = High |
| `due_date` | `INTEGER` (Long?) | DEFAULT NULL | Дедлайн в миллисекундах UTC |
| `is_all_day` | `INTEGER` (Boolean) | DEFAULT 1 | 1 = Весь день, 0 = Точное время |
| `completed_at` | `INTEGER` (Long?) | DEFAULT NULL | Время завершения задачи (UTC, ms) |
| `sort_order` | `INTEGER` (Int) | DEFAULT 0 | Ручной порядок сортировки |
| `rrule` | `TEXT` (String?) | DEFAULT NULL | Задел под движок повторов v1.1 |
| `is_deleted` | `INTEGER` (Boolean) | DEFAULT 0 | Флаг мягкого удаления |
| `created_at` | `INTEGER` (Long) | NOT NULL | Время создания (UTC, ms) |
| `updated_at` | `INTEGER` (Long) | NOT NULL | Время обновления (UTC, ms) |

### 2.4. Таблица: `checklist_items` (Пункты чек-листа)

| Поле | Тип данных | Ограничения | Описание |
|---|---|---|---|
| `id` | `TEXT` (String) | PRIMARY KEY | UUIDv4 пункта |
| `task_id` | `TEXT` (String) | NOT NULL, FK | Ссылка на `tasks.id` |
| `title` | `TEXT` (String) | NOT NULL | Текст пункта |
| `is_done` | `INTEGER` (Boolean) | DEFAULT 0 | 1 = выполнен, 0 = не выполнен |
| `sort_order` | `INTEGER` (Int) | DEFAULT 0 | Позиция в списке внутри задачи |
| `is_deleted` | `INTEGER` (Boolean) | DEFAULT 0 | Флаг мягкого удаления |
| `created_at` | `INTEGER` (Long) | NOT NULL | Время создания (UTC, ms) |
| `updated_at` | `INTEGER` (Long) | NOT NULL | Время обновления (UTC, ms) |

### 2.5. Индексы базы данных

```sql
CREATE INDEX idx_tasks_due_status ON tasks(due_date, status, is_deleted);
CREATE INDEX idx_tasks_project ON tasks(project_id, status, is_deleted);
CREATE INDEX idx_checklist_task ON checklist_items(task_id, is_deleted);
```

## 3. Дизайн-система и изоляция дизайн-токенов

**Архитектурное правило:** Полный запрет на хардкод HEX-цветов, отступов и радиусов внутри Composable-функций. Все стили предоставляются централизованно через `LocalAppColors` и `LocalAppSpacing`.

| Приоритет | Значение в БД | Фон плашки (Светлая тема) | Фон плашки (Тёмная тема) | Пример бейджа |
|---|---|---|---|---|
| **High (P1)** | `5` | `#FFCDD2` | `#5C1D1D` | P1 Высокий |
| **Medium (P2)** | `3` | `#FFE082` | `#543B0C` | P2 Средний |
| **Low (P3)** | `1` | `#BBDEFB` | `#0D3C61` | P3 Низкий |
| **None (P0)** | `0` | `#EEEEEE` | `#242424` | P0 Без приоритета |

Цвет текста бейджей (светлая тема, из исходного макета спецификации): P1 — `#B71C1C`, P2 — `#F57F17`, P3 — `#0D47A1`, P0 — `#424242`.

## 4. Навигация и спецификация экранов

Навигация строится на базе нижнего бара (`BottomNavigationBar`) с 4 табами:

```
┌────────────────────────────────────────────────────────┐
│ [Входящие]     [ Все ]        [Списки]     [Настройки] │
└────────────────────────────────────────────────────────┘
```

### 4.1. Экран «Все» (Главный экран)

- **Секция «Просрочено» (Overdue):**
  - Условие: `due_date < start_of_today AND status = 0 AND is_deleted = 0`.
  - Выделяется акцентным красным заголовком. Скрывается, если просроченных задач нет.
- **Секция «Сегодня»:**
  - **Блок «Весь день» (All-Day):** Задачи на сегодня с `is_all_day = 1`, закреплены вверху списка.
  - **Блок «По времени»:** Задачи на сегодня с точным временем (`is_all_day = 0`), отсортированные по возрастанию (`due_date ASC`).
- **Секция «Предстоящие»:** Задачи с датой позже сегодняшнего дня.
- **UX завершения задачи:** При клике на чекбокс карточка зачеркивается, становится полупрозрачной (alpha 0.4) и через 2.5 секунды плавно скрывается (`delay(2500)`). Показывается Snackbar с кнопкой «Отмена» (Undo).

### 4.2. Экран «Входящие» (Inbox)

Отображает плоский список задач, принадлежащих системному списку `projects.is_inbox = 1` или не имеющих установленного срока (`due_date IS NULL`).

### 4.3. Экран «Списки»

Двухуровневый аккордеон: Папки (`project_groups`) → Списки (`projects`). Отображает счетчик открытых задач напротив каждого списка и кнопки создания новых проектов/папок.

### 4.4. Экран быстрого создания задачи (Fullscreen Quick Add)

- **Вызов:** Плавающая кнопка `[+]` на основных экранах.
- **Форм-фактор:** Полноэкранный оверлей с мгновенным автофокусом на названии и поднятой клавиатурой.
- **Элементы:** Текстовое поле заголовка, поле описания, горизонтальный скролл чипов:
  - Чип `[Дата]`: Сегодня / Завтра / Календарь.
  - Чип `[Время]`: Тумблер Весь день / Выбор точного времени.
  - Чип `[Список]`: Выбор целевого проекта (по умолчанию — текущий или Inbox).
  - Чип `[Приоритет]`: Выбор P0, P1, P2, P5.
  - Чип `[Чек-лист]`: Добавление первого пункта подзадачи.

### 4.5. Экран детального просмотра (Task Detail View)

Полноэкранный экран редактирования всех атрибутов задачи и полноценного управления чек-листом (добавление пунктов, отметка чекбоксов, удаление, переупорядочивание).

### 4.6. Экран «Настройки» (Импорт данных)

Кнопка вызова системного пикера файлов (Storage Access Framework) для выбора CSV-файла бэкапа TickTick. Отображение прогресса, сводная статистика импорта и кнопка полной очистки базы.

## 5. Спецификация Android-виджета (Jetpack Glance)

- **Форм-фактор:** Интерактивный списочный виджет (размер от 4×2 до полного экрана).
- **Шапка виджета:** Заголовок «Сегодня», счетчик открытых задач, кнопка `[+]` (запуск Quick Add в приложении).
- **Тело виджета:** Плавный вертикальный скролл (`LazyColumn`) списка задач на сегодня и просроченных.
- **Интерактивность:**
  - Клик по чекбоксу на виджете **мгновенно** переводит задачу в `status = 2` в Room базе без задержки и без запуска UI приложения.
  - Клик по телу карточки открывает экран задачи (`Task Detail View`) в приложении.

## 6. Движок импорта из CSV TickTick

| Колонка в CSV TickTick | Поле в базе Room | Правило трансформации |
|---|---|---|
| `Folder Name` | `project_groups.name` | Поиск существующей папки или создание новой записи |
| `List Name` | `projects.name` | Поиск или создание списка; если имя «Inbox» → `is_inbox = 1` |
| `Title` | `tasks.title` | Переносится без изменений |
| `Content` | `tasks.content` | Переносится в тело описания задачи |
| `Priority` | `tasks.priority` | Прямой маппинг в целочисленные `0, 1, 3, 5` |
| `Status` | `tasks.status` | `0` (Normal) → `0`; `1` или `2` → `2` (Completed) |
| `Due Date` | `tasks.due_date`, `is_all_day` | Если содержит время → `is_all_day = 0`, иначе `is_all_day = 1` |
| `Completed Time` | `tasks.completed_at` | Парсинг даты завершения в миллисекунды UTC |
| Подзадачи / Checklist | `checklist_items` | Парсинг строк формата `- [ ]` и `- [x]` в отдельные записи подзадач |

## 7. Критерии приемки (Definition of Done)

1. Проект успешно компилируется через команду `./gradlew assembleDebug` без ошибок.
2. База данных Room инициализируется со всеми связями `FOREIGN KEY` и индексами.
3. CSV-файл бэкапа TickTick корректно импортируется с сохранением папок, списков и архивных задач.
4. Экран «Все» корректно группирует задачи на Overdue, All-Day и хронологический таймлайн.
5. Завершение задачи в приложении сопровождается задержкой 2.5 секунды и возможностью отмены через Undo.
6. Виджет Glance размещается на рабочем столе и позволяет закрывать задачи кликом по чекбоксу автономно.

## 9. Официальный бэклог v1.1 (Первая очередь после MVP)

1. **Недельный режим в виджете и приложении (Сетка 2×4):**
   - Матрица из 8 ячеек: интерактивный мини-календарь месяца + 7 дней недели.
   - Верхний тумблер на виджете для мгновенного переключения между сеткой недели и списком.
2. **Движок повторяющихся задач (Recurrence Engine):**
   - Парсинг правил `RRULE` (ежедневно, еженедельно, ежемесячно) и генерация следующего инстанса задачи при завершении текущего.
3. **Локальные уведомления Android:**
   - Фоновые напоминания через `AlarmManager` точно в назначенное время дедлайна.
4. **AI-голосовой ввод (Voice Quick Add):**
   - Запись аудио → Whisper STT → структурирование в JSON через LLM → создание задачи.
5. **Облачная синхронизация и Веб-клиент:**
   - Подключение Supabase (PostgreSQL + Auth), двухсторонняя синхронизация по таймстемпам `updated_at`.
6. **Система тегов:**
   - Отдельная сущность тегов и фильтрация списков по контекстам.

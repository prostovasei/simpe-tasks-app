# Проверки Simple Tasks

## Автоматические

Для изменений приложения: `./gradlew assembleDebug check recordRoborazziDebug`.
Android CI выполняет сборку, тесты/lint/проверку токенов и запись скриншотов.
Перед merge дождаться успешного прогона для последнего коммита PR.
При изменении схемы БД проверить миграцию существующих данных; при общей логике — все затронутые точки входа.

Для Markdown/шаблонов проверить относительные ссылки, отсутствие противоречащих правил,
сохранность исходных архивов и итоговый diff. Обязательный Android CI остаётся условием merge.

## Ручная проверка

Полный чек-лист — [TESTING-CHECKLIST.md](TESTING-CHECKLIST.md): 51 раздел, 364 пункта с прежними ID (экспорт из Claude 10.11.2026, #92).
Пометки там: Б — быстрая проверка после итерации, А — логика покрыта автотестами, Н — новое в последней версии.
История прежних прогонов — [testing-runs/README.md](testing-runs/README.md); исходные данные — `docs/imports/claude-checklist*.json`.
При изменении поведения обновлять затронутые пункты и добавлять новые с уникальным ID в том же PR.

Ниже — короткий smoke-чек-лист, добавленный 10.11.2026 при переходе на два инструмента. Он не заменяет полный
и не является записью прогона; пункты SM-* в исторических прогонах не встречаются.

- [ ] SM-01: обновление APK поверх существующей версии сохраняет задачи, списки и настройки.
- [ ] SM-02: создать задачу, изменить дату/время/список, закрыть и открыть приложение; данные сохранены.
- [ ] SM-03: выполнить задачу и отменить действие; приложение и виджет показывают согласованное состояние.
- [ ] SM-04: проверить «Предстоящее»/«Неделя», переход к «Спискам», поиск и настройки.
- [ ] SM-05: проверить «Входящие», «Когда-нибудь», «Без списка» на задачах с разными датами и списками.
- [ ] SM-06: из виджета открыть задачу, создать новую, переключить вид, вернуться к сегодня нажатием даты.
- [ ] SM-07: напоминание приходит; «Отложить» меняет срок; полоска и уведомление работают согласно настройкам.
- [ ] SM-08: перенос текущего повтора не меняет всю серию; операция со всей серией соответствует выбранному действию.
- [ ] SM-09: удаление, восстановление и «Не буду делать» дают разные ожидаемые результаты.
- [ ] SM-10: затронутый интерфейс проверить в светлой/тёмной теме и при увеличенном шрифте.

В PR добавлять конкретные шаги проверки новой фичи. Тестовые данные для импорта/экспорта — обезличенные.
PM выполняет быструю проверку после итерации; полный регрессионный прогон — перед большим переходом.

## Запись результатов

Для каждой проверки фиксировать:
- версия и build/APK, PR или коммит;
- дата, устройство, Android, launcher (для виджета);
- ID пункта, результат: не проверено / прошло / ошибка;
- наблюдение и Issue для найденной ошибки.

Историю хранить в `docs/testing-runs/<версия>-build<N>.md` либо прикладывать к соответствующему Issue.
Прогоны до 10.11.2026 сведены в [testing-runs/README.md](testing-runs/README.md) — их не переписывать.
Отсутствие результата означает «не проверено». Автотесты не подтверждают ручной прогон на телефоне.

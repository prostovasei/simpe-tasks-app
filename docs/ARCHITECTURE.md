# Архитектура Simple Tasks

## Актуальное устройство на 11.11.2026 (0.61.0)

- Один Gradle-модуль `:app`, один Android APK; серверных микросервисов в этом проекте нет.
- `domain/` — модели, контракты репозиториев и операции; `data/` — Room, DAO, реализации репозиториев, импорт/экспорт.
- `ui/` — Compose, навигация, экраны и ViewModel; `designsystem/` — токены, темы, общие компоненты.
- `widget/` — виджет; `notifications/` — напоминания, полоска и озвучка; `core/` — общие средства, DI, обновление приложения.
- Общая Room-база версии 7; история схем лежит в `app/schemas/`.
- Финансы (#217) — модуль в том же приложении: `domain/model/finance`, `FinanceRepository`, таблицы `finance_*`, экраны `ui/feature/finance` (§4.63–4.64).
- Кроме MainActivity есть TaskPopupActivity и UpdateActivity, а также Activity виджета.
  Старое описание «единственная Activity» ниже относится к начальному плану.
- Android Service для озвучки и полоски — компоненты того же приложения.
- Общие правила работы двух инструментов — [../AGENTS.md](../AGENTS.md).
- Требования — [../SPEC.md](../SPEC.md); состояние — [HANDOFF.md](HANDOFF.md).

## Как читать историю ниже

Сохранён исходный архитектурный аудит и журнал всех итераций, чтобы не потерять обоснования.
Разделы 1–3 и дорожная карта описывают исходный план; вопросы с пометками «нужно решение» не обязательно остаются открытыми.
В разделе 4 более позднее явно принятое решение заменяет раннее по тому же вопросу.
Последние продуктовые решения — §4.60–4.62 (0.55–0.57). При новой фиче обновлять актуальную сводку и добавлять решение с датой/Issue/PR.

## 1. Аудит архитектуры

### 1.1. Схема Room

| # | Статус | Проблема | Решение / правило | Итерация |
|---|---|---|---|---|
| R1 | 🔴 | **Даты «на весь день» в UTC.** `due_date` хранится как UTC-мс. Задача «на 13 октября, весь день», сохранённая как полночь по Москве, в другом часовом поясе окажется 12-м или 14-м числом. Спецификация не говорит, *какой* момент времени хранить для all-day. | All-day: хранить полночь календарной даты **в UTC** («плавающая» дата) и сравнивать по календарной дате. Задачи с временем: реальный момент времени (UTC), сравнение по локальной дате пользователя. Всё сравнение дат — в одном классе `DayBoundaries`. | 02 |
| R2 | 🟠 | **Мягкое удаление ломает каскад.** `ON DELETE CASCADE` не срабатывает при `is_deleted = 1`. Удалили список — его задачи остаются «живыми» и всплывают на экране «Все» и в виджете. | Удаление списка/папки — одна транзакция, помечающая `is_deleted` у всех потомков (папка → списки → задачи → пункты). FK оставляем с `RESTRICT`/`NO ACTION` как страховку от «сирот». | 02 |
| R3 | 🟠 | **Нет индекса на `projects.group_id`.** Room выдаст предупреждение (FK-колонка без индекса) и будет сканировать таблицу целиком. | Добавить `idx_projects_group ON projects(group_id, is_deleted)`. `tasks.project_id` и `checklist_items.task_id` уже покрыты существующими индексами. | 02 |
| R4 | 🟠 | **Системный «Inbox» никто не создаёт** и ничто не гарантирует, что он один. Импорт из TickTick создаст второй Inbox. | Создавать Inbox при первом создании БД (callback) с фиксированным ID. Импорт «Inbox» → сливаем в существующий, а не создаём новый. | 02, 03 |
| R5 | 🔴 | **Противоречие:** «физическое удаление запрещено» vs кнопка «полная очистка базы» в Настройках. | Предложение: очистка — единственное разрешённое физическое удаление (пока нет синхронизации), после очистки пересоздаётся Inbox. Нужно подтверждение PM. | 03 |
| R6 | 🟠 | **Повторный импорт = дубликаты.** UUID генерируются заново, повторная загрузка того же CSV удвоит задачи. | Вариант А (рекомендую): колонка `external_id` (TickTick `taskId`) + пропуск уже импортированных. Вариант Б: предупреждение «сначала очистите базу». | 03 |
| R7 | 🟡 | «Сегодня» вычисляется в момент запроса. Если экран открыт через полночь — секции не пересчитаются. | Поток «текущий день» (`TodayTicker`), который переключается в полночь и перезапускает запросы. | 04 |
| R8 | 🟡 | Room-схема должна экспортироваться с первого дня, иначе миграции для v1.1 (теги, синхронизация) будут писаться вслепую. | `exportSchema = true`, папка `app/schemas` в git. | 02 |
| R9 | 🟡 | `updated_at` должен меняться при *любом* изменении, иначе синхронизация v1.1 потеряет правки. | Обновление метки — только в репозитории через общий `Clock`, не в UI. | 02 |

### 1.2. Импорт TickTick (замечания к разделу 6)

| # | Статус | Проблема | Решение |
|---|---|---|---|
| I1 | 🟠 | В реальных выгрузках TickTick перед строкой заголовков обычно идут служебные строки (дата экспорта, версия, легенда статусов). | Парсер ищет строку заголовков, а не берёт первую строку файла. |

## 2. Структура проекта

### 2.1. Модули

MVP — один Gradle-модуль `:app` со строгими пакетами. Изоляция токенов дополнительно защищается автоматической проверкой сборки (`checkDesignTokens`): HEX-цвета (`Color(0x…)`, `#RRGGBB`) вне `designsystem/tokens` валят сборку. Многомодульность (`:core:designsystem`, `:data`, …) — не раньше v1.1, когда появится синхронизация.

### 2.3. Правила зависимостей

```
            ┌──────────────────────────┐
            │  designsystem/tokens     │  (чистый Kotlin)
            └────────┬────────┬────────┘
                     │        │
        ┌────────────▼──┐  ┌──▼─────────────┐
        │ designsystem/ │  │ widget/theme   │
        │ theme (Compose)│ │ (Glance)       │
        └──────┬────────┘  └──┬─────────────┘
               │              │
          ┌────▼────┐    ┌────▼────┐
          │   ui    │    │ widget  │
          └────┬────┘    └────┬────┘
               │              │
               └──────┬───────┘
                      ▼
                ┌──────────┐
                │  domain  │  ◄──── data (реализует интерфейсы)
                └──────────┘
```

- `domain` ни от чего не зависит.
- `ui` и `widget` не знают про `data` (только через интерфейсы `domain`, связывает Hilt).
- `ui` и `widget` не импортируют `designsystem/tokens` напрямую — только через свою тему.

## 4. Стратегия переезда из TickTick и обновлённая дорожная карта

**Стратегия «переезд с запасным выходом»** (решение PM): импорт без потерь → пробный период → при необходимости выгрузка обратно в CSV TickTick (TickTick импортирует свою резервную копию; дубли PM снимает удалением задач в TickTick перед загрузкой). Синхронизация с TickTick не делается.

### 4.1. Решения по импорту (по реальной выгрузке PM: 3 399 задач, 145 активных)

| Вопрос | Решение |
|---|---|
| Очистка базы (R5) | Единственное физическое удаление; после очистки пересоздаются «Входящие» |
| Чек-листы | В реальном файле маркеры `▪` (выполнено) / `▫` (нет), строки разделены `\r`; разбираются только у задач `Kind = CHECKLIST`. Markdown `- [ ]` в обычных задачах остаётся текстом описания |
| «Весь день» | По колонке `Is All Day` (в `Due Date` время есть всегда); дата — в часовом поясе задачи из колонки `Timezone` |
| Статусы | `0` → активна, `2` и `1` → выполнена, `-1` → **отменена** (отдельный статус) |
| Интервалы времени | `Start Date` хранится в `tasks.start_date`; `Due Date` остаётся сроком |
| Подзадачи | `parentId` → `tasks.parent_id`; удаление родителя удаляет подзадачи |
| Напоминания | Колонка `Reminder` хранится как есть (`tasks.reminders`) до появления уведомлений |
| Остальные поля | Исходная строка CSV целиком хранится в `tasks.source_data` (JSON) — для выгрузки без потерь |
| «Заметки» (`Kind = NOTE`) | Импортируются как обычные задачи (тип сохраняется в `source_data`) |
| Повторы | Правила RRULE хранятся слово в слово; все 39 активных правил PM — стандартные. Режима «после выполнения» у PM нет |
| Порядок | `Order` TickTick → номер позиции внутри списка (1, 2, 3…) |
| Дата создания | Из `Created Time` |

### 4.44. Доработка 0.41.1 — виджет не обновлялся после импорта

- **Симптом (видео и журнал виджета PM):** после импорта 103 задач из TickTick задача, созданная или удалённая из виджета, появлялась или пропадала

- **Причина:** картинка виджета (RemoteViews со всей лентой) уходит рабочему столу одним пакетом; у Android на это общий лимит ~1 МБ.
  На 100+ плашках пакет ~760 КБ на виджет (у PM их два), система молча его не доставляла; рабочий стол брал свежую картинку, только
  когда сам перезапускал виджеты (возврат из приложения). Замер — `WidgetSizeTest`.
- **Решение PM:** «Все» — сегодня и ещё 6 дней с повторами (было 30); просроченных не больше 10 — ближайшие к сегодня, счётчик «Просрочено · N» — все
  (`WidgetModel.hiddenOverdue`); «Входящие» и списки — первые 30; строки «Ещё N» нет. Страховка — не больше 40 плашек (`WidgetModels.ITEMS_MAX`):
  плашка весит ~7 КБ, полный виджет ~283 КБ, меньше трети лимита. В журнал виджета пишется размер пакета («пакет N КБ»).
- Тесты: `WidgetSizeTest` (без ограничений 763 КБ → с ограничениями 233 КБ; полный виджет 283 КБ), `WidgetModelTest` (7 дней, 10 просроченных, 40, 30).

### 4.101. Голосовой ввод: правка текста в окне (#299, 0.82.1)

`VoiceState` теперь хранит подтверждённый `text`, текущую фразу `partial`, флаг `recording` и `error`. Результат распознавателя (в том числе «пауза») только дописывается к `text` через `VoiceErrors.join` и делает первую букву заглавной (`capitalize`, Google возвращает русскую фразу в нижнем регистре); в задачу текст уходит только по «Готово» (`VoiceErrors.result`: заглавная, без точки в конце, запись при этом обрывается). Ошибка при непустом тексте не стирает его: подпись «Не расслышал — нажмите 🎤 ещё раз»; без текста — окно ошибки как в #95. Модель и распознаватель вынесены в `VoiceModel.kt`, окно — `VoiceInput.kt`.

Окно — карточка фиксированной высоты `SizeTokens.VOICE_HEIGHT` под строкой состояния, привязана к верху: клавиатура открывается под ней и её не двигает, длинный текст прокручивается внутри поля. Во время записи поле только показывает текст (последнее слово серым), нажатие на него останавливает запись; на паузе — `BasicTextField` с курсором в конце. `MicButton` — вариант «Дыхание»: бесконечный `rememberInfiniteTransition` (масштаб до 1,1 за 1,2 с) и радиальное свечение, растущее с громкостью; без анимаций системы (`ANIMATOR_DURATION_SCALE == 0`) неподвижен. Кнопка микрофона в виджете — `widget_task_bar_mic` (`accentSoft`) с чёрным значком; `WidgetPalette.accentSoft`.

### 4.102. Перезапуск распознавателя (#302, 0.82.2)

`AndroidVoiceEngine` держит один `SpeechRecognizer` на всё окно: повторный запуск — `cancel()` + `startListening()` того же экземпляра. Раньше каждый запуск уничтожал прежний и сразу создавал новый; сервис Google освобождается асинхронно и отвечал временным кодом, который `VoiceErrors.from` относил к «Распознавание недоступно» (PM видел это только при повторном запуске). Номер запуска (`session`) отбрасывает опоздавшие события прежнего запуска.

Коды разделены: сеть → `NO_NETWORK`, язык → `NO_LANGUAGE`, `ERROR_AUDIO` → `BUSY`, прочие (клиент, отключение сервера, занят, сервер, лимит) → `START_FAILED`. `START_FAILED` до первых слов: распознаватель пересоздаётся и запуск тихо повторяется один раз через 500 мс; второй сбой показывается. `UNAVAILABLE` — только при `isRecognitionAvailable == false`. Каждый код пишется в журнал приложения (`WidgetLog`, «голос: ошибка N»).

### 4.103. Отменённые даты серии (#192, 0.83.0, Room 12)

`Task.skipped: Set<LocalDate>` — даты серии, отменённые по одной; колонка `tasks.skipped_dates` (ISO-даты через запятую, `SkippedDates`), автоматическая миграция Room 11 → 12 только добавляет колонку (NULL), данные не переписываются (`MigrationTest.skippedDatesColumnIsAddedAndRepeatsAreKept`). Все повторы считаются через `nextOccurrence`/`upcomingRepeats` (`Recurrence.kt`): `upcomingRepeats` фильтрует отменённые даты (неделя, «Предстоящие», виджет), `nextOccurrence` их перешагивает (отменённый раз расходует остаток «N раз») и забывает прошедшие. `repeatsBefore` идёт через `nextOccurrence`, поэтому окно «Есть незакрытые повторы» их не перечисляет.

`EarlierRepeats.ONLY` («Только этот») в `RoomTaskRepository.wontDo`: запись `ABANDONED` на дату раза (как прежний «Не буду делать») + дата в `skipped` серии; серия, чек-лист и остаток не меняются. `undoWontDo` восстанавливает прежнюю задачу (вместе с `skipped`) и удаляет запись. Смена правила и «Все повторы с этого момента» отменённые даты сохраняют. Экспорт CSV TickTick их не переносит (в формате нет поля).

### 4.113. ⏸ в окне голоса без ответа распознавателя (#321, 0.89.1)

Раньше ⏸ только вызывал `engine.stop()` (`stopListening`) и ждал `onResult`/`onError`, чтобы показать паузу. После фразы запись тихо перезапускается; `stopListening` до начала новой речи часть распознавателей оставляет без ответа — окно «застревало» в записи. Теперь `pause` в `VoiceRoute` сразу ставит `recording = false` (⏺, серая вода, уровень больше не обновляется), просит `stop()` и ждёт ответ `STOP_GRACE_MILLIS` = 1,5 с (`pausing: Job`); пришёл ответ — ожидание снимается (`settle`), нет — `VoiceEngine.cancel()` (новый метод: номер записи +1, `SpeechRecognizer.cancel()` для незавершённой), недоговорённое — в задачи, без задач и текста — «Не расслышал»; в журнал — «голос: ⏸ без ответа распознавателя». ⏺ до ответа — недоговорённое в задачи и новый запуск (поздний ответ отбросит номер записи). Автопауза 10 с тишины идёт тем же путём.

### 4.111. Анимации окна дня (#314, 0.88.0)

`WidgetClickActivity` для `WidgetClicks.DAY` передаёт `sourceBounds` (место ячейки) в `TaskPopupActivity`, оттуда — `DaySheetRoute(origin)`. `DayViewModel.day(date)` — поток любого дня (кэш `StateFlow`, `WhileSubscribed(5 с)`), выполнение — общий `CompletionTracker`; `state` по-прежнему — день из маршрута (экран «День» в приложении). `DaySheet` (`ui/feature/week/DaySheet.kt`):

Закрытие (`close`) — одно на окно, по завершении `onClose`; в ячейку — только день из маршрута и не развёрнутое окно. `opened` в `rememberSaveable`: при возврате из окна задачи всё сразу на месте;

- резинка — `stretch` (`rubber`: насыщение к `DAY_STRETCH`) добавляется и к пределу высоты, и `Spacer` снизу; `expand` 0 → 1 плавно меняет предел и минимум высоты до всего экрана без системных полос;

Заменяет T-61 (зачёркивание, 70 %, 0,3 с) и бледные цвета выполненных из 0.70.x. Общие константы и анимации — `ui/common/DoneFade.kt`: `DONE_ALPHA` = 0,4, `doneCheck` (заливка кружка за `DONE_CHECK_MS` = 420 мс), `doneAlpha` (после галочки — до 0,4 за `DONE_FADE_MS` = 800 мс, возврат — `UNDONE_MS` = 250 мс), `DONE_TOTAL_MS`. ### 4.109. Скачанные обновления не копятся (#312, 0.86.1)

`GitHubAppUpdater` скачивает APK в `cacheDir` (`UpdateFiles.create`, `update-*.apk`) и передаёт `PackageInstaller`; установщик копирует файл в свою сессию, после чего `commitSession` удаляет файл в `finally` (и при ошибке — повтор скачает заново). `TasksApp.onCreate` в фоне вызывает `UpdateFiles.clear(cacheDir)` — убирает остатки прошлых версий, где файлы не удалялись (у PM было 378 МБ ≈ 20 обновлений). Другие файлы кэша не трогаются.

### 4.108. Несколько задач голосом (#310, 0.86.0)

`VoiceRoute` больше не копит текст: `onResult` превращает фразу в `VoiceTask` (`VoiceTasks.parse` — `SmartDateParser.parse/strip`, срок по умолчанию для вида «Все») и кладёт в `VoiceListModel` (обычная ViewModel записи навигации окна голоса — переживает переход в окно задачи; там же флаг `listening`, чтобы вернуться на паузе). `VoiceTasks.days` группирует по дням, «Без даты» последним. `VoiceSheet` рисует список (`VoiceList`, заголовки `WidgetDates.bar`) над карточкой и счётчик на галочке (`CountBadge`, `SizeTokens.VOICE_BADGE`), отдаёт экранный прямоугольник карточки. `TaskPopup`: нажатие на задачу → `QuickAddDestination(voiceText, voiceTask)` c `LocalSheetOrigin` = место окна голоса (тот же рост из плашки, что из виджета); `QuickAddRoute(onSaved)` → `VoiceListModel.saved(id)` у записи окна голоса. `QuickAddViewModel` с голосовым текстом не пишет и не стирает черновик «+». Галочка → `VoiceTasksSaver.save` (Hilt, `createTask` во «Входящие», `Reminders.default`) и `UndoOffer`; «Отмена» — `deleteTask` + `deleteForever` (навсегда удаляются только задачи из корзины). Уход из окна (правка, сохранение, «Назад») — `engine.destroy()` и недоговорённая фраза в задачи; ⏸ — `engine.stop()`, последняя фраза приходит от движка сама.

### 4.106. Заметные новые новости (#307, 0.85.0)

Лаунчер рисует RemoteViews своим процессом и шрифты приложения (`android:fontFamily="@font/…"`) в виджетах не применяет: текст падает на системный обычный. Поэтому в виджетах жирное задаётся только `textStyle="bold"` (заменены `manrope_600/700` в `widget_news_row_unread`, `widget_news_unread`, `widget_news_day`, `widget_bank_purchase`). Robolectric грузит шрифты в процессе приложения и этот дефект не показывает. Новая новость: `newsMeta` (приложение, `AnnotatedString`) и `newMeta` (виджет, `SpannableString` с `ForegroundColorSpan` + `StyleSpan(BOLD)`) дописывают «Новое» цветом `widget_flat_new`; заголовок в приложении — `manrope_700`.

### 4.107. Непрерывная запись голоса (#308, 0.85.0)

`VoiceRoute`: флаг `listening` (пользователь хочет слушать) и счётчик `speech` (растёт на каждом новом частичном и итоговом тексте). `onResult` при `listening` дописывает фразу и сразу перезапускает распознаватель (`attempt++`), окно остаётся в записи; `NOT_HEARD` при `listening` — тихий перезапуск. `LaunchedEffect(listening, speech)` ждёт `SILENCE_MILLIS` = 10 с и ставит паузу (`listening = false`, `engine.stop()`); последующий `NOT_HEARD` при наличии текста — просто пауза, без ошибки. ⏸, нажатие на текст, галочка и остальные ошибки снимают `listening`; ⏺ ставит его снова. Движок и окно (#302, #305) не менялись.

### 4.104. Прочитанные новости (#300)

`NewsRead` (SharedPreferences `news_read`): ключи прочитанных новостей (как `NewsAlerts.key`, хранятся 48 ч) и флаг первого запуска — тогда вся текущая лента отмечается прочитанной. `newsFeedRows` добавляет строку `Unread(count)` и признак `Article.unread`; приложение (`NewsScreen`, `manrope_600`) и виджет (`widget_news_row_unread`, `widget_news_unread`) рисуют их одинаково. Нажатие на новость и «Прочитать все» отмечают прочитанными: в приложении напрямую, в виджете — через `WidgetNewsLinkActivity` (`EXTRA_NEWS_URL`, `EXTRA_READ_ALL`); после отметки `NewsWidgets.refreshList` перечитывает список виджетов. Прочитанность не связана с уведомлениями (#296): вход во вкладку по-прежнему снимает уведомление, но новости не прочитывает.
